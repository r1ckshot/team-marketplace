# Додати домен-джерело в allowlist

Скіл рідкісний і високоважільний: за весь проєкт домени додавали двічі, і щоразу
процедура відновлювалась із нуля. Ціна помилки не в тому, що «не запрацює» —
а в тому, що частина кроків мовчазна: `verify` червоніє через розбіжність двох
файлів, ipset не оновлюється без Rebuild, а WAF повертає код, який виглядає як
проблема фаєрвола, хоч ним не є.

## Крок 0 — спершу діагноз, а не правка

Перш ніж чіпати списки, з'ясуй, у чому саме проблема. Три коди означають три
різні речі, і додавання домену рятує лише в одному випадку:

```
curl -s -o /dev/null -w '%{http_code}' --max-time 8 https://<домен>/
```

- [ ] **000** — з'єднання не відбулось: домен поза allowlist або DNS не резолвиться.
      Це єдиний випадок, який лікує цей скіл.
- [ ] **403** — запит **дійшов** до сервера, і його відхилив WAF. Додавання в
      allowlist не змінить нічого. Іди в розділ «Пастки», пункт про `tax.gov.ua`.
- [ ] **200 / 301 / 302** — домен уже відкритий. Нічого не роби; редирект це
      норма (`zus.pl` віддає 302, `stat.gov.pl` — 301).

Якщо код 403 — зупинись і скажи Mike прямо: домен технічно доступний, але
машинного читання не буде. Такі джерела лишаються посиланням для людини в
`source_url`, і це нормальний, а не аварійний результат.

## Крок 1 — з'ясувати природу домену

Фаєрвол матчить **резолвлену IP-адресу**, не SNI. Тому apex і `www` — це два
різні записи, і перевіряти їх треба окремо:

```
getent ahostsv4 <домен> | awk '{print $1}' | sort -u
getent ahostsv4 www.<домен> | awk '{print $1}' | sort -u
```

- [ ] Один-два статичні IP → домен триматиметься надійно (як `zakon.rada.gov.ua`,
      193.19.153.66 на власному хостингу).
- [ ] П'ять і більше адрес, та ще й різні для apex і `www` → це CDN/anycast.
      Попередь Mike одразу: такий домен відвалюватиметься після ротації, бо ipset
      наповнюється лише при старті контейнера.
- [ ] Порожньо → DNS не резолвить; додавати нічого, спершу перевір саму назву.

## Крок 2 — `.devcontainer/init-firewall.sh`

Додай рядки в масив `ALLOWED_DOMAINS` — apex і `www` окремо, з коротким
коментарем про природу домену (майбутній читач має розуміти, чого від нього
чекати):

```bash
ALLOWED_DOMAINS=(
  ...
  # <чому цей домен тут; статичний IP чи anycast>
  "<домен>"
  "www.<домен>"
)
```

- [ ] Закриваюча дужка масиву лишається **на початку рядка**. `verify` шукає
      блок регуляркою `ALLOWED_DOMAINS=\(([\s\S]*?)^\)` — якщо дужку зсунути,
      перевірка мовчки перестане бачити частину доменів і стане зеленою без
      предмета перевірки.

## Крок 3 — `.claude/settings.json` (робить Mike)

Ті самі домени йдуть у `sandbox.network.allowedDomains`. **Цей файл Claude Code
не редагує** — не жорсткий permission-prompt, а класифікатор, тож спроба просто
провалиться.

- [ ] Підготуй готовий до вставки блок і віддай Mike дослівно.
- [ ] Дочекайся підтвердження, що він вставив, — і лише тоді йди далі. Крок 4
      без цього завалиться, і причина виглядатиме як твоя помилка.

## Крок 4 — звірка списків

```
npm run verify
```

- [ ] Має бути `OK: домени settings.json ↔ init-firewall.sh збігаються`.
- [ ] `є в settings.json, немає у init-firewall.sh` (або навпаки) — списки
      розійшлись; правь, доки не зійдуться. Розбіжність валить весь `verify`.

## Крок 5 — Rebuild Container

ipset наповнюється **лише при старті контейнера**, тож правка файлу сама по собі
нічого не відкриває.

- [ ] Скажи Mike зробити саме **Rebuild Container**, а не Reopen: Reopen
      перевикористовує старий контейнер зі старим ipset.
- [ ] Поки rebuild не зроблено, не звітуй «домен відкрито» — він ще закритий.

## Крок 6 — що робити з результатом після Rebuild

Відкритий у фаєрволі домен ще не означає читабельний. Прожени `curl` із кроку 0
по кожному хосту окремо (сайт і, якщо є, API-піддомен) — далі три різні
результати, і в кожного свій висновок:

**200 усюди.** Домен придатний як джерело автоматичної звірки. Допиши рядок у
таблицю дозволених доменів в `.claude/rules/environment-limits.md`.

**403 на сайті, 200 на API.** Найчастіший випадок для держустанов: HTML-портал
за WAF, а машинний ендпоінт — ні. Це не поразка: `source_url` для людини лишай
на сайт, а звіряй цифру з API. Так виглядає `nbp.pl` — `www.nbp.pl` за Imperva
(`CNAME zbx4rfg.impervadns.net`), тоді як `api.nbp.pl` сидить на окремій адресі
без того периметра. Перевіряти треба обидва: фаєрвол матчить IP, тож API-хост
потребує **власного** рядка в allowlist, apex його не покриває.

**403 усюди.** Машинної звірки не буде. Домен лишається посиланням для людини в
`source_url`, а цифра береться з іншого джерела або звіряється очима. Це
нормальний результат, а не привід шукати обхід — і його треба записати в
`environment-limits.md`, щоб наступна сесія не пробувала знову.

- [ ] Коміт: `chore(firewall): allow <домен> as a source for <що саме>`. Тіло —
      лише «чому цей домен», якщо з diff не очевидно. Комітити тільки після
      явного «так» від Mike.

## Пастки

Усі — з журналу цього проєкту, не гіпотетичні.

**403 ≠ 000, і додавання в allowlist тут безсиле.** 403 означає, що запит дійшов
до сервера — далі вирішує WAF, а не наш фаєрвол. Конкретні заміряні випадки
(`tax.gov.ua` за Akamai, ротація IP за години) описані в
`.claude/rules/environment-limits.md`; він вантажиться в кожну сесію, тож не
переказуй його тут — звіряйся з ним.

**«Домен раптово відвалився» на CDN — це не баг.** ipset наповнюється при старті
контейнера, а anycast-адреси ротуються. Лікування — Rebuild Container, а не
дебаг iptables. Не витрачай на це сесію.

**Apex не покриває піддомени.** `www.tax.gov.ua` сидить на іншому edge, ніж
`tax.gov.ua`. Додавати треба обидва; перевіряти — теж обидва.

**Не кожне джерело варто відкривати.** У `rules.2026.json` є два записи з
`sip.lex.pl` — домен ніколи не додавали, він віддає 000, і це свідомо: посилання
для людини достатньо. Перш ніж відкривати домен, спитай, чи потрібне саме
машинне читання, чи вистачить `source_url` для читача.

**`~/.claude/settings.json` читається раз на старті сесії.** Якщо Mike правив
персональний файл, зміни підхопить лише наступна сесія — не шукай помилку в
синтаксисі.

**Зелений `verify` без предмета перевірки гірший за червоний.** Це вже ставалось
саме тут: регулярка обривалась на дужці всередині коментаря, і перевірка доменів
проходила, нічого не перевіряючи. Якщо міняєш форматування масиву — переконайся,
що `verify` усе ще бачить усі домени (тимчасово прибери один і подивись, що
перевірка почервоніла).
