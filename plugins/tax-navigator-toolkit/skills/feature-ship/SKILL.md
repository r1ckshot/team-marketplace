# Довести фічу до коміту

Скіл закриває розрив між «код працює» і «задача здана». Розрив реальний і
задокументований: 2026-07-29 роботу тричі оголошено завершеною при застарілому
BACKLOG і чеклісті з невідміченими пунктами, а 2026-08-03 два коміти поїхали в
`master` без запису в `STATE.md` — DoD не дотримали по гарячих слідах.

Порядок нижче — від дешевого до дорогого: спершу машина, потім людина.

## Крок 1 — гейт перевірок, усі чотири

```
npx tsc --noEmit && npm test && npm run test:ui && npm run verify
```

- [ ] `tsc --noEmit` — типи. `next build` у цьому контейнері **заборонений**
      (`.claude/rules/environment-limits.md`), продакшн-збірку валідує Vercel.
- [ ] `npm test` — node-тести + `depcruise` (межі шарів).
- [ ] `npm run test:ui` — jsdom-прохід анкети; окремий конфіг, у `npm test` НЕ входить.
- [ ] `npm run verify` — конфіги, домени, звірка документів.

Червоне — зупинка. Не «допилю після коміту».

## Крок 2 — чи тести взагалі щось тримають

Якщо фіча міняла число, яке бачить користувач, — цей крок веде скіл
`scenario-tests` (мутаційна перевірка). Зелений набір без неї нічого не доводить.

## Крок 3 — Definition of Done, по пунктах

З `CLAUDE.md`, кожен пункт — окремо, з відповіддю «так/ні», а не оптом:

- [ ] «Готово коли» з `docs/STATE.md` виконано — **перечитати сам чекліст**, а не
      згадати його.
- [ ] Тести проходять (крок 1) і звіт фактом: «N node + M UI зелені».
- [ ] Коміти атомарні: один логічний крок = один коміт.
- [ ] `docs/STATE.md` оновлено: немає незакритих `[ ]` від щойно зробленого.
- [ ] `docs/BACKLOG.md`: у NOW не лишилось виконаних рядків; наступна задача
      названа і в STATE, і в BACKLOG.
- [ ] Рішення, що обмежує майбутні вибори, — у `docs/DECISIONS.md`.
      Пояснення саме цієї зміни — у тілі коміта. **Ніколи в двох місцях одночасно.**
- [ ] Візуальна зміна → рев'ю Mike пройдено (`.claude/rules/visual-review.md`).

## Крок 4 — чернетка запису в STATE.md

Запис складається сам — руками або наявним SDK-скриптом:

```
make state-checkpoint        # scripts/state-checkpoint/draft.sh
```

Скрипт бере межу «останній коміт, що чіпав `docs/STATE.md`», і пише чернетку
блоку `Закрито YYYY-MM-DD (...)` у working tree — **не комітить і не пушить**.

⚠️ `is_error: false` не означає «правда»: на живих прогонах агент кілька разів
повертав валідний за схемою, але вигаданий вміст (неіснуючий Makefile-таргет,
невірна кількість тестів). Чернетку **перечитати й звірити з фактами**, і лише
тоді лишати. Відхилити — `git restore docs/STATE.md`.

Запис має відповідати на «що змінилось і чому це важливо», а не переказувати diff.

## Крок 5 — показати Mike і чекати

- [ ] `git status` — переглянути, що саме потрапляє в коміт.
- [ ] Стейджити **за іменами файлів**, не `git add -A` наосліп.
- [ ] Показати diff або список файлів + запропоновані повідомлення комітів.
- [ ] **Дочекатись явного «так».** Без нього не комітити — це тверде правило
      CLAUDE.md, а не ввічливість.

Повідомлення: Conventional Commits, subject і тіло **англійською** (хук
`pre-commit-gate` заблокує кирилицю). Тіло — тільки «чому», коли неочевидно з
diff; для docs-only комітів тіло майже завжди зайве.

## Крок 6 — останній крок DoD

Перечитати `STATE.md` і `BACKLOG.md` очима наступної сесії: чи зрозуміло з них,
де ми і що робити далі. Це не формальність — саме тут ловиться «результат
проголошено, а не звірено».
