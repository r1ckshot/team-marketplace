# tax-navigator-toolkit

## Purpose

Плагін для проєкту, який продає довіру до чисел: інформаційного податкового
навігатора UA↔PL. Закриває два болі, які тут коштують найдорожче — **цифра без
джерела** і **тест, який виглядає зеленим, але нічого не тримає**. Наскрізна фіча
тут щоразу проходить один і той самий довгий ланцюг (правило з `source_url` →
чистий розрахунок → реєстрація в десятьох місцях → еталон → межі шарів), і
забувається в ньому не складне, а нудне.

Не абстрактний інструмент: усе нижче витягнуто з реального заміру — фіча
`umowa zlecenie`, зроблена руками, і те, що в ній виявилось повторюваним
(`CAPSTONE_LOG.md` у репо проєкту).

## Install

```bash
# з локальної теки — під час розробки
claude --plugin-dir ./tax-navigator-toolkit

# з marketplace
/plugin marketplace add r1ckshot/team-marketplace
/plugin install tax-navigator-toolkit@team-marketplace
```

Плагін прив'язаний до конвенцій Tax Navigator (шари `rules → calc → adapters →
presentation`, `rules.2026.json`, `docs/EVIDENCE.md`). В іншому репо він
запуститься, але порадами не влучить.

## Commands

| Команда | Що робить | Приклад |
|---|---|---|
| `/scaffold-rule <rule_id>` | Веде ОДНУ цифру через ланцюг evidence-numbers: перевірка доступності джерела (`curl` → 200/403/000 — три різні гілки), витяг значення, рядок у `docs/EVIDENCE.md`, запис у `rules.2026.json`, анти-дрейф тест. Без аргументу зупиняється й питає `rule_id`, нічого не редагує наосліп | `/scaffold-rule zlecenie.kup` |
| `/scaffold-scenario <slug>` | Веде цілий сценарій порівняння наскрізь і **звітує по кожному з 10 місць реєстрації** (`ScenarioId`, `compareScenarios`, i18n, лендинг, EVIDENCE, SPEC, README, ARCHITECTURE, карта). Забутий пункт не валить тести — він лишає в продукті документ, який бреше | `/scaffold-scenario nierejestrowana` |

## Skills

| Skill | Тригери | Що робить |
|---|---|---|
| `add-source-domain` | «додай домен», «фаєрвол блокує», `curl` віддає `000`/`403`, `/scaffold-rule` зупинився на «джерело поза allowlist» | Спершу **діагноз**: `000` — домен закритий (лікується), `403` — WAF пропустив запит і відхилив (не лікується). Далі синхронна правка `init-firewall.sh` + `settings.json` (розбіжність валить `npm run verify`) і Rebuild Container |
| `scenario-tests` | доданий/змінений сценарій у `calc/scenarios/`, «покрий тестами розрахунок», «додай еталон», «чи ловлять тести регресію» | Еталон виводиться **вручну** з EVIDENCE, звіряється з **центром** смуги (не `rangeContains`), і перевіряється мутацією: код ламається навмисно, тест мусить впасти |
| `feature-ship` | «готово», «можна комітити», «онови STATE», перед будь-яким `git commit` | Гейт із чотирьох перевірок (`tsc`, `npm test`, `test:ui`, `verify`), звірка Definition of Done по пунктах, чернетка запису в `STATE.md`, список файлів на підтвердження — і зупинка до явного «так» |

**Чому `scenario-tests` існує окремо від «напиши тести».** На реальному заміри
свіжий набір тестів був зеленим і пропускав **три навмисні поломки арифметики з
п'яти**: смуга ±4% ковтає похибку в 164 zł/міс. Скіл змушує зробити крок, який
цю дірку показує.

## Hooks

| Event | Matcher / умова | Що робить |
|---|---|---|
| `PreToolUse` | `Bash`, справжній `git commit` | `pre-commit-gate.mjs`: коміт напряму в `master`/`main` → deny; кирилиця в message → deny; message без трейлера `Co-Authored-By` → deny; інакше `npm test` + `npm run verify`, будь-який провал → deny. Відірваний HEAD (rebase, cherry-pick) не блокується, як і коміти, чиє повідомлення не в команді (редактор, `--amend --no-edit`, `-C HEAD`) — трейлера там нема за побудовою. Трейлер звіряється як факт, не як імʼя моделі: воно змінюється разом із `/model`. Підкоманда визначається **розбором токенів**, а не регексом: поле `if:` у `settings.json` не фільтрує, і хук отримує кожну Bash-команду |
| `PreToolUse` | `Bash` | `block-env-writes.mjs`: блокує запис у `.env*` через шелл — редирект, `tee`, `cp/mv`, `sed -i`, пробіли через `$IFS`, inline `node -e` / `python3 -c`. Permission-деній бачить лише `Write`/`Edit`, не шелл |
| `PreToolUse` | `Write\|Edit` | `layer-boundary.mjs`: ті самі п'ять правил, що в `.dependency-cruiser.cjs`, але в момент запису файлу, а не після прогону тестів. Ловить react у `calc/`, адаптери в ядрі, компоненти в `app/lib/**`, пряме читання `rules.2026.json` з UI |
| `PostToolUse` | `Write\|Edit` | Після правки `.tsx`/`.css` нагадує: візуальна зміна не «готова», поки її не побачила людина |
| `SessionStart` | — | Вантажить `.claude/rules/environment-limits.md` проєкту-хоста в контекст: журнал відомих меж середовища читається до планування, а не після |

Кожен хук має ізольований тест поруч (`hooks/test-*.sh`), і кожен перевірений
навмисною мутацією — тобто відомо, що тест справді падає, коли хук зламано:

```bash
bash hooks/test-layer-boundary.sh     # 25 кейсів
bash hooks/test-pre-commit-gate.sh    # 24 кейси
bash hooks/test-block-env-writes.sh   # 21 кейс
```
