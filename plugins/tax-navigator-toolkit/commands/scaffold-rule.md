# Правило `$ARGUMENTS`

Сьогодні: !`date -I`

Наявні `rule_id`: !`grep -o '"rule_id": "[^"]*"' app/lib/rules/rules.2026.json | cut -d'"' -f4 | tr '\n' ' '`

Ця команда веде ОДНУ цифру через ланцюг з `.claude/rules/evidence-numbers.md`.
Задача незворотна за наслідками: неправильне число в проді знецінює всі інші й
помічається не одразу. Тому нижче — точні кроки, а не орієнтири. Крок, який не
закрився, зупиняє роботу; наступний крок не починається «поки що без числа».

## Крок 0 — аргумент

`$ARGUMENTS` порожній → зупинись і попроси `rule_id`. Не вигадуй його зі
здогадки про контекст сесії.

Формат `rule_id`: `<домен>.<що>` у наявній нотації (`residency.`, `common.`,
`jdg.`, `incubator.`, `uop.`, `fop.`). Звір зі списком вище:

- **немає у списку** → новий запис;
- **є у списку** → перезвірка. Тоді `verified_at` оновлюється **завжди**, навіть
  якщо число не змінилось, і в EVIDENCE додається новий рядок. Мовчазна правка
  числа заборонена.

## Крок 1 — джерело, до будь-якого коду

Обери домен за типом цифри:

| Тип цифри | Домен |
|---|---|
| Складки ZUS, 30-krotność, бази | `zus.pl` |
| Ставки й ліміти PIT, KUP | `podatki.gov.pl` |
| Тексти ustaw, Dz.U. | `isap.sejm.gov.pl` |
| Прогнозована середня, обвіщення GUS | `stat.gov.pl` |
| Інтерпретації KIS/KAS | `eureka.mf.gov.pl` |
| Реєстрація діяльності, поділ фінансування | `biznes.gov.pl` |
| ЄСВ, ВЗ, ПКУ — українська сторона | `zakon.rada.gov.ua` |

Перевір доступність ДО всього іншого:

```
curl -s -o /dev/null -w '%{http_code}' --max-time 8 <source_url>
```

Три гілки, всі три обовʼязкові:

- **200 / 301 / 302** → працюємо далі.
- **000 / 403** → **СТОП.** Джерело недоступне: показуємо БЕЗ числа й пояснюємо
  чому. Не підставляй правдоподібне значення й не бери його з памʼяті. Скажи
  Mike, який домен і який код повернувся.
- **Домен поза allowlist** → **СТОП.** Далі веде скіл `add-source-domain`: він
  вирішує, чи домен узагалі варто відкривати, і проводить процедуру. Не
  переказуй її тут і не роби руками.

## Крок 2 — витягти цифру й показати Mike

`WebFetch` по `source_url`. Повідом Mike **три речі**: значення, точне місце в
документі (стаття / пункт / дата обвіщення) і дату документа.

Сторінка не віддає число (JS-рендер, PDF, зміна структури) → **спитай Mike**, не
здогадуйся. Для перезвірки скажи прямо, збіглось значення з наявним у даних чи
розійшлось. Розійшлось — спершу зʼясуй ПРИЧИНУ (інша база? інший рік? інше
припущення?) і назви її, і лише тоді правь. Підтягнути одне до одного, щоб
зійшлось, — заборонено.

## Крок 3 — EVIDENCE перед кодом

Порядок із `evidence-numbers.md` не переставляти: спершу рядок у
`docs/EVIDENCE.md`, потім дані.

Формат наявний у файлі: `Верифіковано <YYYY-MM-DD>: [<назва документа>](<url>)`.
Клади в розділ, що відповідає темі цифри. Якщо цифра нестабільна (щорічне
обвіщення, ветована реформа, sunset-норма) — додай її ще й у §«Нестабільності».

## Крок 4 — дані

`app/lib/rules/rules.2026.json`, форма запису рівно така:

```json
{
  "rule_id": "<домен>.<що>",
  "params": { },
  "source_url": "<url з кроку 1>",
  "verified_at": "<дата з кроку 0>"
}
```

`params` — тільки числа й прапорці, жодного тексту для UI. Якщо форма `params`
нова — додай тип у `app/lib/rules/types.ts`.

## Крок 5 — текст пояснення

Цифра буде видима користувачу → ключ пояснення в `app/lib/i18n/uk.ts`, а не
літерал у компоненті. Це енфорситься `app/lib/__tests__/architecture.test.ts`.
Пояснення каже, ЩО це за число і з чого воно; воно не радить, що обрати.

## Крок 6 — тести, разом із даними

У `app/lib/calc/__tests__/rules.test.ts`:

1. **Анти-дрейф** — тест із самим значенням і з тим, ЯК воно виведене, у назві
   або коментарі (щоб наступний рефактор не зсунув його тихо).
2. **Крос-звірка похідних** — якщо цифра математично зчеплена з іншою
   (`30-krotność = 30 × прогнозована середня`, база duży ZUS = 60% від неї,
   мін. zdrowotna = мінімалка × 9%), закріпи саме звірку: вона ловить помилку в
   будь-якій зі зчеплених цифр.
3. Якщо це відома пастка (цифри ветованої реформи zdrowotnej) — окремий
   анти-регрес, що падає при їх появі.

Еталон виводиться вручну й записується в тест. Тест під код не підганяється.

## Крок 8 — коміти

Два коміти, за прецедентом репо, у порядку кроків:

1. `docs(evidence): verify <тема> against <джерело>`
2. `feat(rules): add <rule_id>` (або `fix(rules): refresh <rule_id> for <причина>`)

Subject англійською, imperative. Тіло — тільки «чому», якщо неочевидно з diff.
